# Переход с ручной установки на панель (tg-xraypanel)

Сценарий: Xray, nginx и подписки на сервере настроены вручную по гайду
(`config.json`, `client-params.env`, `endpoints.list`, `users.list`, `gen-sub.py`).
Нужно поставить панель, **не потеряв подключённых людей**: их UUID и токены
подписок остаются прежними, поэтому все выданные ссылки продолжают работать.

Панель стирает свои данные при установке, поэтому людей сначала выгружают в
файл, а после установки восстанавливают через бота: «🗄 База данных → 📥 Загрузить БД».

## 1. Выгрузка базы (на старом сервере, до установки; нужен только python3)

```bash
git clone https://github.com/<вы>/tg-xraypanel.git /root/xraypanel-src   # или распакуйте архив
cd /root/xraypanel-src

python3 tools/export_manual_stand.py --check        # проверки хоста
python3 tools/export_manual_stand.py                # план: что будет выгружено, ничего не пишется
python3 tools/export_manual_stand.py --out /root    # выгрузка
```

Скрипт читает четыре файла стенда, сверяет их между собой (`XPATH` и `PADKEY`
в `client-params.env` должны совпадать с реальным `config.json`, иначе он
остановится и скажет, что исправить) и пишет два файла с правами 0600:

| файл | зачем |
|---|---|
| `xraypanel_backup_<время>.zip` | **база для бота**: внутри только `xray.json` (ключ сервера, настройки подписок, люди с UUID и токенами) |
| `manual_stand_originals_<время>.tar.gz` | копия четырёх исходных файлов, на всякий случай (бот её не читает) |

**Оба файла содержат приватный ключ сервера и токены людей.** Скопируйте их с
сервера на свой компьютер (`scp`) и не отправляйте в чаты и репозитории.

`_probe` и другие имена, начинающиеся с `_`, считаются служебными: в базу не
попадают, в конфиге Xray остаются как есть.

## 2. Остановите старую автоматику

```bash
systemctl disable --now gen-sub.timer 2>/dev/null     # если настраивали таймер из гайда 9.5
crontab -l | grep gen-sub                             # и cron, если был: удалите строку
```

`gen-sub.py` удаляет из папки подписок всё, чего нет в его `users.list`, и
стёр бы файлы, которые теперь пишет бот. И не запускайте больше
`xray-users.sh`: он переписывает список клиентов целиком.

## 3. Установка панели поверх работающего стенда

```bash
REPO_URL=https://github.com/<вы>/tg-xraypanel.git SKIP_APT_UPGRADE=1 sudo -E bash install.sh
```

- `SKIP_APT_UPGRADE=1` не даёт установщику обновлять все пакеты системы
  посреди миграции (это может перезапустить nginx или xray).
- Панель ставится в `/opt/xraypanel`, юниты называются `xraypanel-*`. До первой
  синхронизации она не трогает ни Xray, ни nginx, ни подписки: работающий
  стенд продолжает работать.

## 4. Восстановление через бота

В боте: **🗄 База данных → 📥 Загрузить БД** и пришлите `xraypanel_backup_….zip`.

Бот восстановит только `xray.json` (остальные файлы свежей панели не
затрагиваются) и сразу выполнит синхронизацию. Что произойдёт:

- Xray **перезапустится один раз** (соединения оборвутся примерно на секунду):
  ручные записи клиентов получат метки `tp:<имя>` (те же UUID, дубликатов не
  будет), служебные записи вроде `_probe` останутся нетронутыми;
- ключ шифрования, `path` и padding в конфиге не изменятся: они уже совпадают;
- бот запишет файлы подписок в `<SUB_DIR>/s/` под **теми же токенами**, то есть
  прежние URL подписок открываются как раньше;
- перед записью бот делает копию конфига: `config.json.bak`.

Заранее посмотреть, что изменится в конфиге, можно командой (ничего не пишет):

```bash
cd /opt/xraypanel
venv/bin/python -m core.xray_cli adopt
```

## 5. Проверка

```bash
cd /opt/xraypanel
venv/bin/python -m core.xray_cli urls                 # страницы подключения всех людей (секретные!)
systemctl is-active xray nginx xraypanel-bot
curl -s https://<домен-подписок>/s/<токен> | base64 -d | head -2     # должны быть vless://
journalctl -u xraypanel-bot -n 30 --no-pager
```

И подключитесь с телефона своей учёткой (`main`).

## Откат

- Конфиг Xray: `cp /usr/local/etc/xray/config.json.bak /usr/local/etc/xray/config.json && systemctl restart xray`.
- Старые файлы стенда остались на месте, плюс `manual_stand_originals_*.tar.gz`.
- Бот перед восстановлением сохраняет текущие файлы рядом с суффиксом `.before_restore`.

## Что дальше после перехода

- Люди из старой базы — «внешние»: срок и статус из `users.json` к ним не
  применяются, карточек в боте у них нет. Управление пока через CLI:
  `python -m core.xray_cli disable <имя>` / `enable <имя>`, затем `publish`.
- Новые клиенты, созданные в боте, получают токен и подписку автоматически.
- Раз в 15 минут `xraypanel-xray-sub.timer` пересобирает подписки (IP узлов
  CDN меняются сами). Если подписки лежат на отдельном хосте, настройте
  доставку: `sub-host/SETUP.md`.
- Каждый пользователь, созданный в панели, получает клиента Xray автоматически
  (UUID и токен подписки), доступ следует его статусу и сроку. Клиентам в боте
  показывается страница подключения с кнопками для Incy / Happ / v2RayTun.
- Доп. устройства: одна ссылка = одно устройство = 100 ₽/мес, ссылка выдаётся
  после оплаты и проверки чека (автоматически по Gemini или админом).
