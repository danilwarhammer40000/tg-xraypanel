# XrayPanel Bot

Telegram-бот для управления клиентами VPN на движке **Xray (VLESS + XHTTP через CDN)**:
добавление/продление/удаление пользователей, подписки подключения (страница с кнопками
для Incy / Happ / v2RayTun), авто-напоминания об истечении, приём чеков об оплате,
AI-автопродление, бэкапы БД, self-hosted деплой через systemd.

**XrayPanel** — отдельный репозиторий на базе tg-trust. Xray здесь единственный движок:
каждый пользователь панели автоматически получает клиента Xray (UUID и токен подписки),
доступ следует статусу и сроку из `users.json`. Подписки отдаёт отдельный хост
(`sub-host/`), людей из ручной установки Xray можно перенести без потери ссылок
(**`ADOPT.md`**). Каталог `/opt/xraypanel`, юниты `xraypanel-*`.

Это форк-рефакторинг [оригинального репозитория](https://github.com/danilwarhammer40000/trusttunnel_botpannel) —
см. `CHANGELOG.md` за полным списком отличий и обоснованием каждого изменения.

```

  bot.py               — ЕДИНСТВЕННЫЙ entrypoint: грузит .env, включает все
                          роутеры из handlers/, запускает polling
  config.py            — BOT_TOKEN/ADMIN_ID + сам объект Bot
  states.py            — все aiogram FSM StatesGroup в одном месте
  keyboards.py         — клавиатуры, общие для нескольких handlers/-файлов
  formatting.py        — форматирование текста карточки/сообщений (без роутера,
                          без зависимости от aiogram)
  pagination.py        — постраничный вывод списков (paginate/pagination_nav_row)
  display.py           — настройки отображения списков + сортировка + метки 🔔/🔸
  access.py            — is_admin/admin_only/run_sync — общее почти для всех хендлеров
  auto_renewal_hook.py — async-мост между хендлерами и core/auto_renewal.py
  handlers/

    client_menu.py        — Мой статус, Моя ссылка, Реквизиты, 📖 Инструкция
    feedback.py            — ✉️ Написать администратору (+ проверка "это чек?")
    receipt.py               — приём чека от клиента + апрув/реджект админом
    auto_renewal_review.py    — 🤖 Автопродление (вкл/выкл) + карточки проверки
    broadcast.py               — 📢 Рассылка (всем / выбранным / проверка привязок)
    database.py                 — 🗄 База данных (экспорт/импорт/управление триалами)
    sorting.py                   — ⚙️ Сортировка БД

    add_user.py                    — ➕ Add user (один / несколько)
    list_users.py                   — 📋 List users + меню действий над пользователем
    leader_link.py                   — «👑 Назначить ведущим» (связка мульти-девайс клиентов)
    extend.py                        — раздел "⏳ Extend" из меню действий
    mass_delete.py                    — 🗑 Удаление пользователей

  dates.py             — единая точка правды для парсинга/сравнения дат

  service.py           — полная синхронизация: клиенты Xray + файлы подписок
  connect.py           — что открывает клиент: страница подключения / vless-ссылка
  notify.py            — синхронная отправка через Bot API
  xray.py              — Xray: клиенты/ключ сервера в xray.json, синхронизация конфига
  subscription.py      — подписки: токены, ссылки по входам CDN, файлы + rsync на хост
  xray_cli.py          — CLI: preflight / adopt / export-db / users-template / import-users / urls / publish / enable / disable
  users_import.py      — перенос «внешних» клиентов Xray в базу панели: ведомые и сроки

  xray_adopt.py        — adopt: план + симуляция первой синхронизации

  auto_renewal.py      — AI-автопродление: настройки, красноярское временное окно,
```

**Кто чем владеет (для FSM-состояний):** каждое состояние (`AddUser.*`,
`ExtendUser.*`, `MassDelete.*` и т.д. — см. `bot/states.py`) обрабатывается
хендлерами ровно в одном файле из `handlers/`. Другой файл может *перейти*
в чужое состояние (например, `list_users.py` включает `AdminMessage.personal`,
а обрабатывает его `feedback.py`) — это нормально и задокументировано в
докстринге каждого файла, где это происходит. Порядок `dp.include_router(...)`
в `bot/bot.py` из-за этого не влияет на поведение: у каждого `callback_data`
и каждого состояния ровно один владелец.

## Установка

```bash
REPO_URL=https://github.com/<вы>/tg-xraypanel.git sudo -E bash install.sh
```

Спросит `BOT_TOKEN` и `ADMIN_ID` и поднимет всё через systemd. Xray и nginx ставятся
отдельно (на сервере или по гайду); панель управляет списком клиентов Xray и файлами
подписок. `SKIP_APT_UPGRADE=1` отключает `apt upgrade` (нужно при установке поверх
работающего стенда). Поверх ручной установки Xray: **`ADOPT.md`**.

## Обновление

```bash
sudo bash /opt/xraypanel/deploy.sh
```

Тянет `git pull`, обновляет зависимости и systemd-юниты (если менялись), перезапускает бота,
шлёт админу сообщение об успехе/неудаче.

## AI-автопродление по чеку (опционально)

Читает скрин/PDF чека через Gemini API и может автоматически продлевать
доступ — с обязательным пост-фактум подтверждением админом. Включается
кнопкой **«🤖 Автопродление»** в меню бота (сама кнопка есть всегда, но
включить тумблер нельзя без настроенного `LOG_CHANNEL_ID` — правило «всё
логируется» соблюдается принудительно, не на словах).

**Условия срабатывания** (любое из двух, при включённом тумблере;
все значения ниже редактируются прямо в боте — см. «Настройка условий»):
1. **Ночное окно** (по умолчанию 22:00–06:00 по Красноярску) — сразу при
   поступлении чека. Либо **«🚀 Полностью автоматический режим»** —
   отдельный тумблер, при котором ночное окно вообще не проверяется,
   попытка идёт на каждый чек круглосуточно.
2. **Заявка висит без ответа администратора дольше порога** (по умолчанию
   3 часа) — в любое время суток, проверяется таймером
   `xraypanel-auto-renewal-check.timer` каждые 15 минут.

**Кто что решает:** Gemini только **читает** чек — извлекает сумму, дату
платежа, получателя, оценку своей уверенности. Одобряет или отклоняет
**не ИИ, а обычный Python-код** (`core/auto_renewal.py:
evaluate_receipt_extraction`) по жёстким правилам (все — с настраиваемыми
порогами):
- сумма ≥ мин. суммы и кратна ей (по умолчанию 100₽, тариф 100₽/мес)
- дата платежа — не старше N дней от сегодня по красноярскому времени
  (по умолчанию 1 = сегодня/вчера)
- уверенность распознавания ≥ порога (по умолчанию 0.75)

Если хоть одно условие не выполнено (или чек вообще не прочитался) —
заявка **не** продлевается автоматически. Карточка с чеком и полным
набором кнопок (➕1мес/➕2мес/✍️/❌, как при обычном ручном одобрении)
всё равно приходит администратору — плюс кнопка **«🔄 Повторить
автопроверку»**, полезная если причина была временной (например,
устаревшее имя модели Gemini) — так не нужно ничего искать в 📋 List users.

**Настройка условий** — кнопка «⚙️ Настроить условия» в меню
«🤖 Автопродление» показывает все 6 параметров, тап на любой — бот
попросит новое значение текстом и провалидирует его (границы: время
ЧЧ:ММ, суммы/часы положительные, уверенность 0–1 и т.д.) прежде чем
сохранить. Кнопка «↩️ Сбросить по умолчанию» возвращает исходные пороги,
не трогая сам тумблер вкл/выкл.

**После автоодобрения** доступ продлевается сразу (клиент не ждёт, пока
админ проснётся), а админу приходит карточка с самим чеком и кнопками
**«✅ Подтвердить»** / **«🚫 Отключить»** — второе не просто гасит доступ,
а полностью откатывает и статус, и дату истечения к тому, что было до
автопродления.

**Лог-канал:** каждая заявка (с файлом) и каждое решение — автоматическое
или ручное — пишется в канал, куда бот добавлен администратором
(`LOG_CHANNEL_ID` в `.env`). Если отправка в канал не удаётся (самая
частая причина — у бота не включено право «Публикация сообщений» в
настройках канала, одного статуса «администратор» недостаточно), админ
получает явное диагностическое предупреждение в личку — раньше это падало
молча и было незаметно.

**Настройка:**
1. Получить бесплатный ключ на https://aistudio.google.com/apikey
2. Создать приватный Telegram-канал, добавить бота администратором **с
   правом «Публикация сообщений»** (не просто «администратор» — это
   отдельная галочка), узнать numeric ID канала (например, через
   @userinfobot или пересылку сообщения из канала в @JsonDumpBot)
3. Указать `GEMINI_API_KEY` и `LOG_CHANNEL_ID` при установке (`install.sh`
   спросит) или прописать вручную в `.env` и перезапустить бота
4. Включить тумблер кнопкой «🤖 Автопродление» в меню бота

Без `GEMINI_API_KEY`/`LOG_CHANNEL_ID` весь остальной функционал бота
работает как обычно — фича полностью опциональна и по умолчанию выключена.

## Xray (VLESS + XHTTP через CDN) и подписки (опционально)

Только для администратора и по включению для каждого пользователя («🛰 Xray» в
карточке). Всё хранится в `data/xray.json` (в бэкапе): ключ сервера, настройки
подписок и клиенты (`uuid`, секретный `token`, `enabled`). Срок и статус
берутся из `users.json`, поэтому одна подписка управляет обоими VPN.

Как это работает:
- На каждой синхронизации (`core.service.full_resync_and_reload` и таймер
  `xraypanel-xray-sub.timer`, раз в 15 минут: IP узлов CDN меняются сами)
  `core/xray.py` приводит конфиг Xray к состоянию «кто активен», а
  `core/subscription.py` пишет по файлу `data/sub-out/<токен>` (base64 со
  ссылками `vless://`, по одной на каждый вход CDN) и доставляет папку rsync-ом
  на **отдельный хост подписок** (порт 443 основного сервера обычно занят).
- Отключённый, истёкший или перевыпущенный клиент теряет файл: старый URL
  подписки отвечает 404. «🔄 Выдать новую ссылку» меняет и UUID, и токен.
- Админу бот показывает страницу подключения `https://<домен>/join.html#<токен>`
  (кнопки Incy / Happ / v2RayTun) и прямой URL подписки. Если подписки не
  настроены, показывается прежняя одиночная ссылка `vless://`.
- Маршрутизация (российские сайты напрямую) приезжает вместе с подпиской в заголовках
  ответа: `autorouting` для Incy и `routing` для Happ (`sub-host/gen_routing.py`), клиентам
  не нужна отдельная кнопка.
- Входы CDN (`endpoints`: `domain`, `resolve`, список фиксированных IP) и
  параметры ссылки (`uplink_get`, `xmux`, `sess_key`) задаются в
  `xray.json["subscription"]`, пример и настройка хоста: `sub-host/`.

CLI (на сервере с ботом): `venv/bin/python -m core.xray_cli preflight|adopt|export-db|users-template|import-users|urls|publish|enable|disable`.
Переход с ручной установки (люди, UUID и токены сохраняются, восстановление через бота): **`ADOPT.md`**.

Важно: клиентские параметры подписки (`path`, ключ padding, шифрование) должны
совпадать с живым конфигом Xray. Панель сама правит в нём только `decryption`,
`path` и padding; `sessionKey`, `xmux` и прочее остаётся как настроено.

## Разработка и тесты

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements-dev.txt

```

## Переменные окружения

См. `.env.example`. Обязательные: `BOT_TOKEN`, `ADMIN_ID`.
`XRAY_AUTO=0` отключает автоматическую выдачу клиентов Xray (останется ручное включение в карточке).

## Известные ограничения / что дальше

- Бот работает от `root` (нужен `systemctl restart xray`, запись в конфиг Xray и в папку подписок).
  Юнит `xraypanel-bot.service` ограничивает запись через `ReadWritePaths`
  (`/usr/local/etc/xray`, `/var/www/sub`, `/opt/xraypanel`); другие пути добавляются
  через `systemctl edit xraypanel-bot.service`.
- Пароли пользователей хранятся в открытом виде (это соответствует модели: сервер
  должен уметь их читать). Файлы БД теперь принудительно
  получают права `600` при каждой записи.
- Ни один хендлер пока не покрыт end-to-end тестами против живого aiogram
  (только `core/dates.py` и `core/db.py` — см. `tests/`). Для `bot/handlers/`
  структура теперь это позволяет сделать точечно, файл за файлом.
